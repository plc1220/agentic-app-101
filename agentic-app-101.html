Speaker notes

01 / The big idea

Think of an agent as a helpful assistant with a small toolbox.

You ask“When is the backend session?”
→
AI decides“I should look that up.”
→
Tool checksFinds the workshop schedule
→
AI replies“9:30 AM.”

The AI can only use the tools the application makes available.

Speaker notes

Keep it concrete. This workshop schedule lookup will be the running example. A tool here is just a Python function with a clear job.

02 / The pieces

A real app has a few familiar parts.

Screen

What you see

A chat box or a web page.

App

What connects things

Receives the question and shows the answer.

AI

What understands

Works out whether a tool might help.

Tool

What does a job

Looks up the approved information.

There is still an application behind the AI, with ordinary software and data.

Speaker notes

Avoid jargon like orchestration or middleware unless someone asks. Give the analogy of a restaurant: customer-facing menu, staff coordinating, chef, and a bounded task.

03 / Where information lives

Different information needs different homes.

PlaceThink of it asExample
DatabaseA tidy list of recordsPeople, orders, job status
Object storageA big-file cupboardPDFs, photos, generated reports
Working filesA desk for the current taskTemporary notes or extracted text
CacheA quick-access sticky noteSomething useful to reuse briefly

Ask: does it need to be kept, and who should be able to see it?

Speaker notes

Introduce DB as orderly durable records; object store as durable files; workspace as temporary work area; cache as speed-up. Don't dwell on vendor products or implementation details.

04 / Containerization

A container is a packed lunchbox for an app.

Recipe

Image

The app and the ingredients it needs.

Lunchbox

Container

The packed app while it is running.

Cupboard

Separate storage

Where files go when they must be kept.

Containers help apps run consistently. Important files need a proper place outside the disposable container.

Speaker notes

Say “containerization is a way to package and start software consistently.” Avoid explaining container internals unless the group asks. Note that this take-home demo does not need Docker.

Speaker notes

Demystify function calling: AI returns a structured request; the program decides what function exists, runs it, and sends the result back. This example has no side effects.

09 / Looking ahead

More capable apps need more care.

Protect

Who can do what?

Give each tool only the access it needs.

Remember

What should be saved?

Choose where records and files live.

Recover

What if something fails?

Handle errors, timeouts, and repeat attempts.

Start with a small helpful task. Add more powers only when they are needed.

Speaker notes

Connect back to storage and containers. These choices become important as we move from a local sample to multiple people using the app.

10 / Remember

Keep the first agent simple.

One

A tool is a small job

Make the action clear and bounded.

Two

Data has different homes

Records, big files, temporary work, and cache differ.

Three

People stay in control

The app decides what the AI may do.
